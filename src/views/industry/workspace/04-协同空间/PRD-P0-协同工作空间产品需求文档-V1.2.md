## 1. 产品概述

### 1.1 产品定位

协同工作空间是平台的核心基础模块，为租户提供数据组织和团队协作的容器。类比企业中的"事业部"组织架构，工作空间是所有后续业务数据（产品结构、BOM、文档、零件等）的归属载体。

### 1.2 设计参考

参考 **3DEXPERIENCE 协同工作空间** 的**基线角色（Baseline Roles）** 设计理念：
- 角色权限逐级继承
- 分为业务用户角色与管理角色两大类
- 基于基线角色实现权限分层

### 1.3 核心价值

| 价值点 | 说明 |
|-------|------|
| 📦 数据隔离 | 不同业务线的数据在不同工作空间中隔离管理 |
| 👥 团队协作 | 成员基于工作空间进行协作，权限精细化控制 |
| 🚀 开箱即用 | 租户创建时自动生成默认工作空间，用户自动加入 |
| 🏠 个人目录 | 每个用户在每个工作空间有专属 Home 文件夹 |
| 🔐 层级权限 | 基线角色逐级继承，权限边界清晰 |

## 2. 协同空间角色体系设计

### 2.1 角色层级模型

协同工作空间基于**基线角色（Baseline Roles）** 实现权限分层，角色权限逐级继承，分为**业务用户角色**与**管理角色**两大类。

```
┌─────────────────────────────────────────────────────────┐
│                    管理角色（2个）                         │
│  ┌───────────────────────────────────────────────────┐  │
│  │  所有者（Owner）                                   │  │
│  │  ↑ 空间完整控制权                                  │  │
│  └───────────────────────────────────────────────────┘  │
│                          ↓ 继承                          │
│  ┌───────────────────────────────────────────────────┐  │
│  │  管理员（Administrator）                           │  │
│  │  ↑ 空间管理权限                                    │  │
│  └───────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────┘
                          ↓ 继承
┌─────────────────────────────────────────────────────────┐
│                   业务用户角色（5个）                       │
│  ┌───────────────────────────────────────────────────┐  │
│  │  领导者（Leader）                                  │  │
│  │  ↑ 可管理公共资源                                  │  │
│  └───────────────────────────────────────────────────┘  │
│                          ↓ 继承                          │
│  ┌───────────────────────────────────────────────────┐  │
│  │  作者（Author）                                    │  │
│  │  ↑ 可创建正式业务对象                              │  │
│  └───────────────────────────────────────────────────┘  │
│                          ↓ 继承                          │
│  ┌───────────────────────────────────────────────────┐  │
│  │  贡献者（Contributor）                             │  │
│  │  ↑ 可创建评估类内容                                │  │
│  └───────────────────────────────────────────────────┘  │
│                          ↓ 继承                          │
│  ┌───────────────────────────────────────────────────┐  │
│  │  读者（Reader）                                    │  │
│  │  ↑ 访问空间全部内容                                │  │
│  └───────────────────────────────────────────────────┘  │
│                          ↓ 继承                          │
│  ┌───────────────────────────────────────────────────┐  │
│  │  公共读者（Public Reader）                         │  │
│  │  ↑ 仅访问公开内容                                  │  │
│  └───────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────┘
```

### 2.2 业务用户角色（5个）

业务用户角色面向普通团队成员，权限逐级继承，共 5 个基线角色。

| 角色 | 权限继承 | 核心能力 | 数据操作边界 |
|-----|---------|---------|-------------|
| **公共读者（Public Reader）** | 无（最底层） | 仅访问协作空间内**公开内容** | 只读；无创建 / 修改 / 删除 |
| **读者（Reader）** | 继承公共读者 | 访问协作空间**全部内容** | 只读；可创建个人收藏夹 / 文件夹（私有） |
| **贡献者（Contributor）** | 继承读者 | 可创建**评估类内容** | 可创建评审、评论、批注、标记等非正式内容 |
| **作者（Author）** | 继承贡献者 | 可创建**正式业务对象** | 可创建产品结构、BOM、文档、零件等正式数据 |
| **领导者（Leader）** | 继承作者 | 可管理**公共资源** | 可管理公共文件夹、资源库、空间模板等 |

### 2.3 管理角色（2个）

管理角色面向空间运维人员，权限高于业务用户角色。

| 角色 | 权限继承 | 权限范围 | 核心管理能力 |
|-----|---------|---------|-------------|
| **管理员（Administrator）** | 继承领导者 | 单个协作空间 | 管理空间成员、配置空间属性、管理角色权限、查看操作日志 |
| **所有者（Owner）** | 继承管理员 | 单个协作空间 | 空间完整控制权、可删除空间、可变更任意成员角色、可转移所有权 |

### 2.5 角色设计原则

1. **逐级继承原则**：每个角色自动继承下一层角色的所有权限
2. **最小权限原则**：新成员默认授予最低层级的合适角色
3. **层级清晰原则**：角色边界清晰，避免权限交叉
4. **可扩展原则**：支持在基线角色基础上自定义扩展权限

## 3. 用户故事与验收标准

### 3.1 工作空间管理

#### US-001：租户管理员创建工作空间

**作为** 租户管理员  
**我想要** 创建新的协同工作空间  
**以便** 组织不同业务线的数据和团队

**验收标准：**
- [ ] 可输入工作空间名称（必填，2-50字符）
- [ ] 可输入工作空间编码（必填，唯一，2-32字符，英文+数字）
- [ ] 可选择工作空间类型（TEAM/ PROJECT，默认 TEAM）
- [ ] 可选择权限级别（Public/Protected/Private，默认 Public）
- [ ] 可输入描述（可选，最多500字符）
- [ ] 创建成功后，创建人自动成为该空间的 **Owner**
- [ ] 创建成功后，系统自动生成 7 个基线角色
- [ ] 创建成功后，系统自动生成提示信息

---

#### US-002：查看工作空间列表

**作为** 登录用户  
**我想要** 查看我加入的所有工作空间列表  
**以便** 了解和切换工作上下文

**验收标准：**
- [ ] 列表展示字段：空间名称、空间编码、权限级别、角色、状态、创建时间
- [ ] 支持按名称搜索
- [ ] 支持按权限级别筛选
- [ ] 支持按状态筛选
- [ ] 默认空间有明显标识（如"默认"标签）
- [ ] 列表按创建时间倒序排列
- [ ] 支持分页（每页10/20/50条）

---

#### US-003：查看工作空间详情

**作为** 工作空间成员  
**我想要** 查看工作空间的详细信息  
**以便** 了解空间配置和成员情况

**验收标准：**
- [ ] 展示空间基本信息（名称、编码、类型、权限级别、描述、状态、创建人、创建时间）
- [ ] 展示成员统计（总人数、各角色人数）
- [ ] 展示成员列表（头像、姓名、角色、加入时间、最后访问时间）
- [ ] 成员列表支持搜索和筛选
- [ ] Owner/Administrator 可见"编辑"和"成员管理"按钮
- [ ] Leader 及以下角色仅可见查看按钮

---

#### US-004：编辑工作空间

**作为** 工作空间 Owner 或 Administrator  
**我想要** 编辑工作空间的基本信息  
**以便** 更新空间配置

**验收标准：**
- [ ] 可修改工作空间名称
- [ ] 可修改权限级别
- [ ] 可修改描述
- [ ] **不可修改**工作空间编码
- [ ] 编辑需二次确认
- [ ] 保存后立即生效，列表同步更新
- [ ] 记录操作日志

---

#### US-005：删除工作空间

**作为** 工作空间 Owner  
**我想要** 删除不再需要的工作空间  
**以便** 清理无效数据

**验收标准：**
- [ ] 删除按钮仅 Owner 可见
- [ ] 点击删除后弹出二次确认对话框
- [ ] 确认框中明确提示"删除后不可恢复"
- [ ] 若空间有成员，提示"请先移除所有成员"，禁止删除
- [ ] 若空间无成员，可执行删除
- [ ] 删除成功后从列表中移除
- [ ] 记录删除操作日志

---

#### US-006：切换工作空间

**作为** 登录用户  
**我想要** 在顶部导航栏快速切换工作空间  
**以便** 在不同业务上下文中工作

**验收标准：**
- [ ] 顶部导航显示当前工作空间名称
- [ ] 点击显示下拉列表，展示所有加入的工作空间
- [ ] 默认空间置顶显示
- [ ] 点击切换后，页面刷新并加载新空间上下文
- [ ] 切换后，Home 文件夹自动切换为对应空间的用户 Home
- [ ] 切换成功有提示信息
- [ ] 切换操作记录日志

### 3.2 成员管理

#### US-007：添加空间成员

**作为** 工作空间 Owner 或 Administrator  
**我想要** 添加租户内用户为空间成员  
**以便** 邀请团队成员协作

**验收标准：**
- [ ] 可从租户用户列表中选择多个用户（批量选择）
- [ ] 可选择分配的角色（Public Reader/Reader/Contributor/Author/Leader/Administrator/Owner，默认 Reader）
- [ ] 不能添加已在空间中的用户
- [ ] 添加前显示确认信息（即将添加的用户列表和角色）
- [ ] 添加成功后，用户自动获得对应角色的权限
- [ ] 添加成功后，自动为新成员创建该空间的 Home 文件夹
- [ ] 系统记录添加操作日志
- [ ] 可选：给新成员发送通知

---

#### US-008：移除空间成员

**作为** 工作空间 Owner 或 Administrator  
**我想要** 移除空间中的成员  
**以便** 维护成员列表

**验收标准：**
- [ ] 移除按钮仅 Owner/Administrator 可见
- [ ] Administrator 不能移除 Owner
- [ ] 不能移除最后一个 Owner（至少保留1个 Owner）
- [ ] 点击移除后弹出二次确认
- [ ] 确认后成员从空间移除
- [ ] 移除后，该成员的 Home 文件夹保留（标记为已离开）
- [ ] 移除后，成员创建的数据保留（所有权转移给空间）
- [ ] 记录移除操作日志

---

#### US-009：变更成员角色

**作为** 工作空间 Owner 或 Administrator  
**我想要** 变更成员的角色  
**以便** 调整权限配置

**验收标准：**
- [ ] 角色变更按钮仅 Owner/Administrator 可见
- [ ] Administrator 不能变更 Owner 的角色
- [ ] 可将成员角色改为 7 个基线角色中的任意一个
- [ ] 变更前显示确认信息（原角色 → 新角色，权限变化说明）
- [ ] 变更后立即生效
- [ ] 记录角色变更操作日志

---

#### US-010：查看成员列表

**作为** 工作空间 Administrator 及以上角色  
**我想要** 查看空间的所有成员列表  
**以便** 了解团队构成

**验收标准：**
- [ ] 列表展示：头像、姓名、角色、加入时间、最后访问时间
- [ ] 支持按姓名搜索
- [ ] 支持按角色筛选
- [ ] 支持按加入时间排序
- [ ] Owner 在列表中置顶显示
- [ ] 显示成员总数统计
- [ ] 点击角色可查看该角色的权限说明

#### US-014：查看空间角色体系

**作为** 工作空间成员  
**我想要** 查看空间的角色体系和各角色权限说明  
**以便** 了解权限层级

**验收标准：**
- [ ] 以层级结构图展示 7 个基线角色的继承关系
- [ ] 点击每个角色可查看详细权限列表
- [ ] 展示当前用户在该空间的角色位置
- [ ] 展示角色权限对比表格（可选）

### 3.3 系统自动化

#### US-011：租户创建时自动生成默认工作空间

**作为** 系统  
**我想要** 在租户创建时自动生成一个默认工作空间  
**以便** 租户开箱即用

**验收标准：**
- [ ] 租户创建成功后，系统自动触发
- [ ] 默认空间名称："默认工作空间"
- [ ] 默认空间编码："default" + 租户ID（保证唯一）
- [ ] 默认权限级别：Public
- [ ] 默认空间类型：TEAM
- [ ] 标记为系统默认空间（不可删除）
- [ ] 自动生成 7 个基线角色
- [ ] 创建成功记录系统日志

---

#### US-012：用户创建时自动加入默认工作空间

**作为** 系统  
**我想要** 在新用户创建时自动将其加入租户的默认工作空间  
**以便** 用户登录即可开始工作

**验收标准：**
- [ ] 用户创建成功后，系统自动触发
- [ ] 自动查找租户的默认工作空间
- [ ] 将用户添加为默认工作空间的 **Reader** 角色
- [ ] 自动为用户创建该空间的 Home 文件夹
- [ ] Home 文件夹命名规则："Home_{用户名}_{空间编码}"
- [ ] 记录系统操作日志

---

#### US-013：用户加入工作空间时自动创建 Home 文件夹

**作为** 系统  
**我想要** 在用户加入任何工作空间时自动创建该空间的 Home 文件夹  
**以便** 用户有专属工作目录

**验收标准：**
- [ ] 用户加入工作空间（无论自动还是手动添加）后触发
- [ ] Home 文件夹归属用户
- [ ] Home 文件夹通过 workspace_uid 关联到工作空间
- [ ] Home 文件夹命名规则："Home_{用户名}_{空间编码}"
- [ ] Home 文件夹默认权限：仅所有者可写入，其他成员按空间权限
- [ ] Home 文件夹不可删除、不可重命名、不可移动
- [ ] 创建成功记录日志

## 4. 业务规则矩阵

| 规则ID | 规则描述 | 适用场景 | 违反后果 |
|-------|---------|---------|---------|
| BR-001 | 工作空间编码在租户内唯一 | 创建/编辑空间 | 提示"编码已存在"，操作拒绝 |
| BR-002 | 有成员的工作空间不允许删除 | 删除空间 | 提示"请先移除所有成员"，操作拒绝 |
| BR-003 | 每个租户有且仅有一个默认工作空间 | 系统初始化 | 违反数据一致性，需人工干预 |
| BR-004 | 每个工作空间至少有一个 Owner | 成员管理 | 禁止移除最后一个 Owner |
| BR-005 | Administrator 不能操作 Owner 角色 | 成员管理 | 权限不足，操作拒绝 |
| BR-006 | Home 文件夹不可删除/重命名/移动 | 文件夹管理 | 系统级保护，无操作入口 |
| BR-007 | 切换工作空间自动切换 Home 上下文 | 空间切换 | 页面刷新，Home 同步切换 |
| BR-008 | 归档状态的空间不允许创建新内容 | 内容创建 | 提示"空间已归档"，操作拒绝 |
| BR-009 | 不能添加已在空间中的用户 | 成员添加 | 提示"用户已在空间中"，跳过 |
| BR-010 | 移除成员不删除其创建的内容 | 成员移除 | 内容保留，所有权转移给空间 |
| BR-011 | 角色权限逐级继承 | 权限校验 | 上层角色自动拥有下层角色的所有权限 |
| BR-012 | 基线角色不可删除 | 角色管理 | 7 个基线角色为系统内置，不可删除 |
| BR-013 | 基线角色名称不可修改 | 角色管理 | 基线角色的名称为系统保留，不可修改 |
| BR-014 | 新成员默认授予 Reader 角色 | 成员添加 | 可手动调整为其他角色 |
| BR-015 | 一个成员在一个空间只能有一个角色 | 成员角色分配 | 变更角色时覆盖原有角色 |

## 7. 异常场景处理

| 场景 | 触发条件 | 系统处理 | 用户提示 |
|-----|---------|---------|---------|
| 删除有成员的空间 | 空间成员数 > 0 | 拒绝删除操作 | "该工作空间仍有成员，请先移除所有成员后再删除" |
| 移除最后一个 Owner | 尝试移除空间中唯一的 Owner | 拒绝移除操作 | "不能移除工作空间的最后一位所有者，请先指定新的所有者" |
| Administrator 操作 Owner | Administrator 尝试移除或变更 Owner 角色 | 拒绝操作 | "权限不足：管理员不能操作所有者" |
| 添加已存在的成员 | 添加已在空间中的用户 | 跳过该用户，其他继续 | "用户 XXX 已在空间中，已跳过" |
| 编码重复 | 创建/编辑时编码已存在 | 拒绝保存 | "工作空间编码已存在，请更换编码" |
| 切换到无权限的空间 | 用户手工构造URL访问未加入的空间 | 跳转到403页面 | "您无权访问此工作空间" |
| Home 文件夹创建失败 | 用户加入空间时 Home 创建异常 | 记录错误日志，重试3次 | 管理员收到告警，用户端不感知 |
| 空间已归档仍操作 | 在已归档的空间中创建内容 | 拒绝操作 | "该工作空间已归档，不允许创建新内容" |
| 删除基线角色 | 尝试删除系统内置的7个基线角色 | 拒绝操作 | "基线角色为系统内置，不可删除" |
| 修改基线角色名称 | 尝试修改基线角色的名称 | 拒绝操作 | "基线角色名称不可修改" |

| 操作日志 | 所有关键操作必须记录审计日志 |

3. ✅ **分类清晰**：业务用户角色（5个）+ 管理角色（2个）
4. ✅ **权限边界明确**：每个角色有清晰的核心能力和数据操作边界
5. ✅ **系统内置保护**：基线角色不可删除、名称不可修改
